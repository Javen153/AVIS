# Архитектура AVIS

## Поток данных

```
WASAPI loopback ──► Resampler ──► AudioCapture ring ──► FrontendStream (FE-v1)
   (NAudio)          48 кГц         SPSC              192 полосы × 100 Гц
                                                              │
                                                    FrontendFrame
                                                              ▼
                                             IObjectSource (Neural | DSP | Mock)
                                                              │
                                                       AnalysisFrame
                                                    (объекты + отладка)
                                                              ▼
                                        Renderer (D3D11) ──► SwapChainPanel
                                                              │
                                                       FrameJson (JSONL)
```

Анализ идёт в отдельном потоке; UI-поток только читает последний `AnalysisFrame`
(ленивая публикация через `Volatile.Read/Write`). Захват — кольцевой буфер SPSC,
поэтому аудио-поток не блокируется рендером.

## Границы модулей

- `Avis.Core` — контракты (`IObjectSource`, `FrontendFrame`, `AnalysisFrame`),
  FE-v1 на C#, трекер, параметры объектов, DSP, ONNX-источник, настройки, JSONL,
  WAV/PNG/ресемплер. Без UI, рендера и NAudio.
- `Avis.Audio` — WASAPI loopback (NAudio), ресемплер, SPSC-кольцо. Зависит только
  от Core.
- `Avis.Render` — D3D11 (Vortice + P/Invoke), HLSL, bloom, офскрин и PNG.
  Зависит только от Core.
- `Avis.App` — WinUI 3: окно, панель настроек, оверлей, скриншоты, бенчмарк.
  Композирует всё.
- `Avis.Cli` — `analyze|render|check|bench|parity|capture-test`.

## FE-v1

- 192 полосы, лог-шкала 30 Гц – 16 кГц.
- Три разрешения FFT: 2048 (низ), 1024 (середина), 512 (верх); причинные окна.
- Выход: `P_M`, `P_L`, `P_R` (мощность), `bandsDb_M`, 576 признаков
  (dB + дельты), время.
- Python-эталон (`ml/avis_ml/frontend.py`) и C# (`runtime/src/Avis.Core/Frontend.cs`)
  сверяются по golden-векторам: максимум |diff| ≈ 4e-6 при лимите 2e-3.

## Модель M-v1

- Вход: `feat [1,3,192]`, состояние `h_in [2,1,384]`.
- GRU 2 слоя × 384, головы: эмбеддинг 20 (L2), активность (sigmoid), питч, салиентность.
- Экспорт: ONNX opset 17, `dynamo=False`; паритет PyTorch/ONNX Runtime ≤1e-3
  (факт ≈2e-6).
- Инференс: ONNX Runtime CPU, один поток на op (по умолчанию), тензоры и буферы
  переиспользуются.

## ObjectTracker

1. Полосы с `act ≥ порога` привязываются к активным объектам по косинусу эмбеддингов.
2. Свободные полосы кластеризуются по лидеру; устойчивые кластеры дают кандидатов.
3. Кандидат с достаточным числом попаданий рождает объект; банк отпечатков
   возвращает прежний ID (re-ID) и цвет.
4. Мягкое членство (cos-softmax) распределяет полосы между объектами.
5. Центроиды и отпечатки обновляются EMA; близкие объекты сливаются; пропавшие
   гаснут и уходят в банк.

Параметры (порог активности, окна рождения/затухания, слияние, банк) вынесены
в настройки.

## Рендер

- Аддитивные сплаты: инстансный буфер (stride 48 байт), HDR-таргет, bloom,
  композит в sRGB, опционально шлейфы/водопад.
- X — панорама, Y — частота (log/erb/mel/linear), размер/яркость — громкость и
  салиентность, цвет — палитра или PCA тембра.
- Офскрин-режим (`avis-cli render`) и скриншоты используют один и тот же код;
  PNG пишется с alpha=255 (премультиплицировано над чёрным).

## Потоки и задержка

- Аудио-поток: захват → ресемплер → ring.
- Поток анализа: ring → фронтенд (hop 10 мс) → модель → трекер → публикация кадра.
- UI-поток: таймер → рендер последнего кадра.
- Задержка «звук → кадр» ≈ hop + инференс + трекер (p95 измеряется в App/CLI).
