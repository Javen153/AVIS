## B. Что строим

Программа для Windows захватывает весь системный звук (WASAPI loopback) и в реальном времени рисует его так, как его **воспринимает человек**. На обычном спектре часто не видно того, что слышно. Пример: гитара или голос внутри «стены звука» шугейза. Здесь каждый слышимый источник виден как отдельный **объект**, и видно, как он меняется. Шум тоже показывается, а не подавляется. Визуализатор универсален (любая музыка), лёгкий и без заметной задержки.

**Главный критерий:** глядя на экран, можно чётко увидеть звук, который слышишь, и как он меняется.

### Правила объектов
1. Один синус → одно чёткое пятно.
2. Частота меняется плавно (свип, глиссандо, вибрато) → тот же объект, плавно движется по X.
3. Появился независимый звук (свой момент начала и/или свой тембр) → новый объект.
4. Гармонический звук (гитара, голос, синт) → **один** объект на основном тоне. Гармоники **не рисуются**: мозг слышит один объект.
5. Один инструмент, играющий разные ноты и аккорды, → один объект. Он двигается и меняет форму.
6. Шум — объект. Тихий белый шум → тусклая широкая область на весь диапазон.
7. Ударные раздельно: бочка, малый, хэт, тарелки, томы — отдельные объекты.
8. Бэк-вокал — отдельный объект от основного вокала.
9. Реверберация и хвосты принадлежат объекту-источнику.
10. **Цвет объекта стабилен всю песню**, даже если объект затих и вернулся.
11. Число объектов не фиксировано.

### Визуализация (основной вид — «сейчас», без истории по умолчанию)
- **X — частота** слева направо. Шкала: log (по умолчанию) / ERB / mel / linear. Диапазон по умолчанию 30 Гц–16 кГц, настраивается.
  - Позиция объекта: основной тон, если tonality ≥ 0.4, иначе спектральный центр в log-частоте.
- **Y — громкость объекта как целого.** Режимы: абсолютная (по умолчанию) / частичная (partial) / заметность (salience). Шкала −70…0 дБ.
- **Объект — мягкое градиентное пятно** (анизотропный гауссов сплэт), не геометрическая фигура:
  - ширина: тональный — узкий; шумовой — от 10-го до 90-го перцентиля энергии по частоте;
  - мягкость края зависит от тональности;
  - яркость — от громкости или заметности (настройка).
- **Аккорды (настройка):** (а) одно вытянутое пятно от нижней до верхней ноты; (б, по умолчанию) отдельное пятно того же цвета на каждой ноте.
- **История (настройка):** выкл (по умолчанию) / шлейфы с затуханием / водопад.
- Ударные — вспышки с отдельными атакой и затуханием.
- Фон прозрачный (виден Mica/Acrylic), есть bloom.
- **Цвет (настройка):** (по умолчанию) палитра по порядку появления, шаг оттенка по золотому сечению в OKLCH; либо цвет из тембрового эмбеддинга (PCA-проекция из `model.json`, угол → оттенок).
- **Отладочные виды:** 1) спектрограмма; 2) спектрограмма, раскрашенная по объектам; 3) таблица объектов (id, высота, громкость, заметность, тональность, presence, возраст); 4) 2D-проекция эмбеддингов.
- Принцип: **«правильность» и «красота» разделены.** Визуальные настройки не влияют на анализ.

## E. Фронтенд FE-v1 и модель

### Фронтенд (эталон — Python `frontend.py`; C# должен совпадать)
**Все матрицы весов генерирует Python** и сохраняет в `shared/frontend/v1/weights.bin` (+ описание раскладки в `frontend.json`). C# только загружает их.

- Вход: стерео float32, 48000 Гц. Шаг H=480 отсчётов (10 мс). Окна каузальные (последние N отсчётов, начало заполнено нулями).
- STFT-разрешения N ∈ {4096, 2048, 1024, 512}, окно Ханна (periodic), `rfft`. Мощность бина: `P=|X|²/(Σw)²`.
- F=192 полосы, центры `fc_k = 30·(16000/30)^(k/191)`. Выбор разрешения: fc<400→4096; <1600→2048; <5000→1024; иначе 512.
- Веса — треугольники в log-частоте с вершиной в `fc_k` (вес 1), основание от `fc_{k-1}` до `fc_{k+1}`. Для крайних полос сосед отражается. Веса не нормируются.
  - Если в треугольник попало <2 бинов, полоса — линейная интерполяция мощности между двумя ближайшими бинами (веса в сумме 1).
- Каналы: M=(L+R)/2, S=(L−R)/2, L, R. Для каждого `P_M, P_S, P_L, P_R = Σ w·P_bin`.
- Признаки модели `[3,192]`, где `dB(x)=10·log10(x+1e-12)`:
  - `feat0=(dB(P_M)+60)/30`;
  - `feat1=(dB(P_S)+60)/30`;
  - `feat2=clip((dB(P_L)−dB(P_R))/20, −1, 1)`.
- `FrontendFrame` в C# также отдаёт `bandsDb_M`, `P_M`, `P_L`, `P_R`.
- C#: собственная radix-2 FFT (float, предвычисленные twiddle, без аллокаций на кадр).
- **Тест паритета** на golden (детерминированный стерео-сигнал 3 с: синусы 55/440/3000 Гц, свип, розовый шум −30 дБ, щелчки, разная панорама): `max|Δ|≤2e-3`, `mean|Δ|≤2e-4`. Полосы с `dB(P_M)<−110` исключить.

### Модель M-v1 (строго каузальная; свёрток по времени нет, память только в GRU)
```
x [B,T,3,192] → по частотной оси как [B·T,3,192]
enc1: Conv1d(3,48,k5,p2)+GELU, Conv1d(48,48,k5,p2)+GELU            → s1 [48,192]
enc2: Conv1d(48,64,k5,s2,p2)+GELU, Conv1d(64,64,k5,p2)+GELU         → s2 [64,96]
enc3: Conv1d(64,64,k5,s2,p2)+GELU                                   → e [64,48]
flatten 3072 → LayerNorm → Linear(3072,384) → GRU(384,384,2 слоя, batch_first) → Linear(384,3072) → reshape [64,48] + e
dec2: ConvTranspose1d(64,64,k4,s2,p1) + s2 → Conv1d(64,64,k5,p2)+GELU
dec1: ConvTranspose1d(64,48,k4,s2,p1) + s1 → Conv1d(48,48,k5,p2)+GELU
head: Conv1d(48,23,k1): emb=L2norm(ch0..19) [192,20]; act=sigmoid(ch20); pitch=sigmoid(ch21); sal=sigmoid(ch22)
```
- `forward(x,h0)` — для обучения. `step(feat[1,3,192], h_in[2,1,384]) → (emb, act, pitch, sal, h_out)` — для экспорта.
- ≈4–5 млн параметров. Цель: ≤1.5 мс/кадр на CPU, 1 поток.
- **Тест:** покадровый `step` на 300 кадрах == `forward` (`max|Δ|≤1e-4`).

### Миксер (torch на GPU)
Пример — 4 с (400 кадров) стерео 48 кГц.
- 25% — полностью процедурные; иначе K=2–8 источников.

| Источник | Вероятность |
|---|---|
| vocal_lead | 0.6 |
| vocal_back | 0.3 (нет в данных — синтетический: сдвиг ±3–7 полутонов и 30–200 мс, панорама ±0.4–0.9) |
| bass | 0.6 |
| ударные | 0.6 (2–4 отдельных барабана) |
| тональные | 1–3 |
| шум | 0.4 (как отдельный источник) |

- Разные источники стартуют в разное время (смещение 0–2 с; в 30% случаев одновременно). Аккорд одного инструмента — один источник.
- Уровни: от −30 до 0 дБ относительно самого громкого. В 30% примеров один тональный источник тихий (−18…−26 дБ).
- Панорама (constant-power): vocal_lead ∈ [−0.1, 0.1], остальные ∈ [−1, 1].
- Аугментации на источник:

| Аугментация | p | Параметры |
|---|---|---|
| дисторшн | 0.3 | tanh, drive 1–30 |
| реверберация | 0.4 | синтетический IR, RT60 0.3–6 с, wet 0.1–0.9 |
| хорус/дилей | 0.2 | — |
| EQ | 0.3 | 1–3 biquad |
| скорость | 0.3 | ±2 полутона (метки высоты масштабируются) |

- Мастер: компрессор p=0.5, лимитер p=0.5, нормализация RMS −20…−8 dBFS.
- Метки на кадр×полосу (тем же torch-фронтендом):
  - `active: dB(P_M^mix) > max(−80, max_clip_dB−60)`;
  - `dominant = argmax_s P_M^s`;
  - `weight = active·clip((dB−порог)/30, 0.1, 1)`;
  - `pitch` — гауссы σ=1 полоса по нотам тональных источников (RMS в кадре > −60 дБ);
  - `sal = sigmoid((dB(P^dom) − dB(Σ_{s≠dom} P^s))/6)` на active.
- Декодирование: читать куски `soundfile` с seek из активных сегментов, ресемплировать на GPU. DataLoader `num_workers=4`, `persistent_workers`, `if __name__=="__main__":`. Воркеры только читают аудио.
- Цель ≥20 примеров/с на GPU.

### Лоссы и обучение
- `L = L_dc + 0.5·L_act + 1.0·L_pitch + 0.5·L_sal`.
  - `L_dc` — взвешенный deep clustering в эффективной форме: `‖VᵀWV‖² − 2‖VᵀWY‖² + ‖YᵀWY‖²`, нормировка на `(Σw)²`, только active.
  - `L_act` — BCE; `L_pitch` — BCE с pos_weight=10; `L_sal` — MSE на active.
- AdamW lr 1e-3, wd 1e-4, warmup 1000 шагов + cosine, grad clip 5, AMP (при NaN или ошибках cuDNN — GRU в fp32).
- Батч 16 при VRAM ≥6 ГБ, иначе 8. OOM → вдвое меньше, запись в DECISIONS.
- Чекпойнт каждые 2000 шагов (`ckpt_last.pt` + лучший по val), обязателен `--resume`. CSV-лог: step, loss, l_dc, l_act, l_pitch, l_sal, lr, sec_per_step.
- Конфиги: `smoke.yaml` (500 шагов), `v1.yaml`, `v1_long.yaml` (дообучение на 12-секундных клипах, lr 2e-4, для стабильности ID).
- **Бюджет времени:** измерь sec/step на smoke и выбери число шагов v1 так, чтобы обучение заняло ≤ ~10 ч (но не больше 100 000 шагов). Запиши в DECISIONS.
- Первым делом прогони smoke (loss должен упасть ≥30%, resume должен работать).

### Пост-обработка (C#, `Avis.Core`; все числа — настройки)
**Кластеризация кадра (`ObjectTracker`):**
1. Активные полосы: `act≥0.5` и `bandsDb_M≥−80`.
2. Полоса назначается активному объекту с max `cos(emb, centroid)`, если ≥0.60.
3. Остальные полосы — leader-кластеризация (cos ≥0.70) → кандидаты.
   - Кандидат, присутствующий ≥5 из 8 последних кадров с энергией >−70 дБ, рождается объектом.
   - Перед рождением сверка с **банком**: `cos(centroid, fingerprint) ≥ 0.75` → старые ID и цвет.
4. `centroid ← norm(0.95·c + 0.05·mean_emb)`; `fingerprint ← norm(0.995·fp + 0.005·mean_emb)` (когда presence>0.5).
5. Мягкая принадлежность: softmax по объектам `cos/τ`, τ=0.1.
6. Слияние: два объекта с cos(centroid) ≥0.85 в течение 50 кадров → слить (остаётся старший ID).
7. Нет полос 15 кадров → `fading`; через 60 кадров исчезает с экрана, но остаётся в банке 60 с.
8. Максимум 24 активных объекта.

**Параметры объекта (`ObjectParams`, общие для Neural и DSP).** Для полос k: `m_k` — принадлежность, `E_k = m_k·P_M[k]`.
- `loudnessDb = dB(Σ E_k·a_k)`, `a_k` — A-взвешивание.
- `partial`: `N'(x)=x^0.23`; `Σ max(0, N'(E_k) − 0.3·N'(E_rest_k))`, затем в дБ-подобную шкалу `10·log10(partial^(1/0.23)+1e-12)`.
- `salience` = среднее `sal_k`, взвешенное по `E_k`, умноженное на presence.
- `pitches`: локальные максимумы `pitch_k·m_k > 0.3`, уточнение параболой по трём полосам и ещё одной параболой по `bandsDb_M` (±2 полосы). Цель — точность ±20 центов на синусе. До 6 штук.
- `tonality = max(pitch_k·m_k)·(1 − spectral_flatness(E))`.
- `centroidHz` — экспонента от энерго-взвешенного среднего `log fc`; `lowHz`/`highHz` — 10-й и 90-й перцентили.
- `envelope[32]` — сумма E по 32 группам по 6 полос.
- `pan` — взвешенное среднее `(dB(P_L)−dB(P_R))/20`.
- `isTransient`: loudnessDb выросла на >6 дБ за 3 кадра.
- `presence = clip((loudnessDb+70)/20, 0, 1)`.

**`DspObjectSource` (запасной режим):**
1. Пики `bandsDb_M` (выше соседей на 6 дБ и выше −70 дБ).
2. Гармоническая группировка: от самого низкого пика кандидаты f0, пики около `n·f0 ±3%` присоединяются (до 20 гармоник).
3. Остаток энергии — объект «шум». Широкополосные транзиенты — объект «удар».
4. Трекинг по |Δlog f0| <1 полутон/кадр и похожести огибающей. Re-ID по средней огибающей.

## G. Рантайм, UI, настройки

**Потоки:**
1. **Аудио** (колбэк NAudio): только копирование в lock-free SPSC-кольцо (стерео float, 4 с), без аллокаций и блокировок. Многоканальный звук → стерео (`L=FL+0.707C+0.707SL`, аналогично R). Обработай форматы IEEE float и 16/24-bit PCM.
2. **Анализ** (AboveNormal): ждёт ≥H отсчётов. Устройство не 48 кГц → ресемплинг (Эрмит). Нет данных 20 мс → подставляет тишину (loopback молчит при тишине). Цепочка `Frontend → IObjectSource → AnalysisFrame`. Публикация снимка через `Volatile.Write`.
3. **Рендер**: `Present(1,0)`, ≥144 FPS (= частоте монитора). Берёт последний снимок и сглаживает параметры критически демпфированной пружиной (жёсткость — настройка). Без аллокаций в цикле.
- Смена устройства по умолчанию (`IMMNotificationClient`) → перезапуск захвата.
- Задержка = метка прихода пакета → метка публикации снимка; p50/p95 в оверлее.

**Рендер (`Avis.Render`), один код для окна и для offscreen-текстуры (CLI/PNG; без GPU — WARP):**
1. Сплэты: инстансинг квадов, пиксельный шейдер — анизотропный гаусс с мягкостью; аддитивное смешивание в HDR `R16G16B16A16_FLOAT`.
2. Bloom: 5 уровней вниз/вверх.
3. Тонмаппинг ACES-аппрокс.
4. Выход premultiplied alpha, `alpha=clamp(max(r,g,b))`.
5. Спектрограмма — отдельный проход. Шлейфы — текстура с затуханием. Водопад — кольцевая текстура.
6. Текст оверлея (FPS, таблица) — в XAML поверх `SwapChainPanel`.

**UI (`Avis.App`):**
- Окно: `MicaBackdrop` (или `DesktopAcrylicBackdrop` — настройка), тёмная тема, `ExtendsContentIntoTitleBar`.
- `SwapChainPanel` во всё окно, все контейнеры `Background="Transparent"`, очистка RT в (0,0,0,0).
- Справа `SplitView` с панелью настроек: `Expander` по группам, контролы **автоматически** из атрибутов (число → Slider+NumberBox, bool → ToggleSwitch, enum → ComboBox).
- Сверху `CommandBar`: источник (Neural/DSP/Mock), вид, пресет. Внизу — строка состояния: FPS, задержка, модель, устройство.
- Режим оверлея: без рамки, поверх всех, клик-сквозь (`WS_EX_TRANSPARENT|WS_EX_LAYERED` через P/Invoke), выход Ctrl+Shift+O.
- Аргументы: `--source mock|dsp|neural --bench <сек> --bench-out <json> --autoclose --set group.name=value --screenshot <png>`.

**Настройки:**
- Класс `AppSettings` с атрибутами `[Setting(Group, Label, Description, Min, Max, Step)]`. Label и Description — на русском.
- JSON в `%LOCALAPPDATA%\AVIS\settings.json`, пресеты в `…\presets\*.json`, встроенные «Точный», «Красивый», «Отладка». Применяются на лету.
- Группы:
  - **Захват:** устройство, усиление.
  - **Анализ:** шкала и диапазон X.
  - **Нейросеть:** модель (список из `/models`), провайдер CPU/DirectML, порог act, макс. объектов.
  - **Трекинг:** все числа из F.
  - **Громкость:** режим Y, диапазон дБ, гамма, что управляет яркостью.
  - **Визуал:** размер и мягкость сплэтов, влияние тональности, bloom, сглаживание, атака/затухание (обычные и ударные), режим аккордов, история, видимость шума 0..1, палитра или цвет по тембру, прозрачность.
  - **Окно:** материал, поверх всех, оверлей.
  - **Отладка:** вид, оверлей FPS/задержки, запись JSONL.
