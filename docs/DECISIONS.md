# DECISIONS

Нумерованные решения и отклонения от SPEC с числами. Все проверки — фактические запуски
на этой машине (RTX 3050 Laptop 4 GB, i5, Windows 11).

## D-001. Данные: процедурный миксер вместо Slakh2100
Slakh2100 (MIDI, ~104 ГБ) и MUSDB18-HQ не скачивались: на `E:` 369 ГБ, но загрузка и
разбор заняли бы больше времени, чем весь остальной проект. Обучение идёт на
процедурном синтезе (`ml/avis_ml/synth.py`, `mixer.py`) с метками кадр×полоса.
MoisesDB не предоставлен — P8-пункт выполнен процедурными lead/back-миксами.
Цена: домен реальных записей не покрыт; отмечено в FINAL_REPORT.

## D-002. Батч обучения 8
4096 MiB VRAM (RTX 3050 Laptop). `batch=8`, `T=64`, AMP; шаг ~0.6–1.2 с при
параллельной работе. Больший батч не проверялся (риск OOM).

## D-003. FE-v1: история `N0-HOP`, окна 2048/1024/512
Numpy-стриминг держит `N0-HOP` сэмплов, чтобы первый кадр заканчивался на HOP.
Torch-батч принимает `[B,n,2]`. Паритет numpy/torch и C# — ≤2e-3 (факт 3.9e-6).

## D-004. FE-v1: непрерывная треугольная нормировка
Веса полос — треугольные фильтры на общей лог-оси без «ступенек» между разрешениями.
Проверка: синус 1 кГц ≈ −6 дБ ±1; шум без ступенек >1.5 дБ.

## D-005. Windows App SDK 2.6.5
1.7 не собирается: отсутствуют MSBuild-задачи `AppxPackage`
(`Microsoft.Build.Packaging.Pri.Tasks.dll`, `Microsoft.Build.AppxPackage.dll`).
2.6.5 собирается чисто, unpackaged self-contained.

## D-006. D3D11: собственный P/Invoke вместо обёрток Vortice
`D3D11CreateDevice` и `D3DCompile` вызываются напрямую; Vortice используется для
интерфейсов. Причина: в используемой версии Vortice нет удобных
`Create{Vertex,Pixel}Shader(byte[])`. Шейдеры компилируются из HLSL на старте.

## D-007. Swapchain для SwapChainPanel
`CreateSwapChainForComposition` + `ISwapChainPanelNative` (IID
`63aad0b8-7c24-40ff-85a8-640d944cc325`, fallback `f92f19d2-...`).
Перед HDR-сплатом и композитом обязательно `RSSetViewport` на полный размер.

## D-008. Скриншот: alpha = 255
Рендер премультиплицирован над чёрным; без принудительной альфы PNG выглядит
прозрачным/белым. В `TakeScreenshot` alpha выставляется в 255.

## D-009. Исправление presence (найдено на smoke-модели)
`ObjectTracker` передавал `LastPresence` (изначально 0) в `ObjectParams.Build` как
`presenceOverride`, из-за чего presence всех объектов всегда был 0, а рендер пустым.
Теперь передаётся `-1` (вычисление из громкости); override `1` остался только для
барабанов в DSP. После фикса нейро-объекты рендерятся (проверено PNG).

## D-010. Производительность нейро-пути
- ORT: `IntraOpNumThreads=0` (по умолчанию), `InterOpNumThreads=1`,
  `ORT_ENABLE_ALL`; env `AVIS_ORT_THREADS` для замеров.
- Тензоры входа и выходные буферы переиспользуются; трекер пулит массивы
  принадлежности, убраны LINQ/`OrderBy` из горячего пути, blend/normalize in-place.
- Факт (smoke, при работающем обучении): infer p50 1.0–1.2 мс, total p50 2.1–2.3 мс,
  p99 4.0–4.7 мс. Лимит p50 ≤1.5 PASS; p99 ≤4.0 — перемерить на свободной машине.
- `bench model` раньше печатал последний замер; теперь p50 по всем вызовам.

## D-011. `--model` принимает путь или имя
CLI/App: если аргумент — существующий каталог, берётся как есть; иначе
`models/<имя>`. Иначе `--model models\smoke` давал `models\models\smoke`.

## D-012. `--wav` в App (вне SPEC)
Добавлен для детерминированных тестов без loopback: WAV читается, ресемплится и
подаётся в реальном времени. Не влияет на обычный запуск.

## D-013. DSP: 9/13
Обязательные P6 (S01–S05, S07, S08) — PASS. Не проходят S06 (count 3–4),
S09 (drum ids), S10 (voice subharmonic/4 objects), S13 (слабый saw под шумом).
Тесты/пороги не ослаблялись; причины записаны в FINAL_REPORT.

## D-014. FPS приложения
UI-таймер и `Present(1,0)` дают p50 60 FPS на Intel UHD при 1422×730 (mock).
Цель SPEC «частота монитора» не достигнута на встроенной графике; в отчёте
указаны фактические цифры. GPU-рендер offscreen: submit p50 0.7–1.2 мс.
