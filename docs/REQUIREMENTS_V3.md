# Требования к M-v3 (рабочая версия, 2026-11-12)

## Задача
Новая рабочая версия нейросети, обученная на доступных датасетах
(MUSDB18-HQ, Slakh2100-redux, процедурный синтез), с архитектурой, выбранной
по измерениям, а не по аналогии. Нужно сохранить контракт шага ONNX и
показать, что v3 лучше v1/v2.1 по осям, на которых предыдущие версии
проваливались.

## Что уже измерено (baseline)
| метрика | v1 | v2.1 | провал v2.1 |
|---|---|---|---|
| S01–S13 | 9/13 | 10/13 | S04, S09, S13 |
| MUSDB pitch AP (6 клипов) | 0.1298 | 0.1099 | ниже v1 |
| MUSDB pitch precision | — | ~0.075 | много ложных пиков |
| Slakh pitch AP | 0.3996 | 0.5137 | — |
| tracking id_switches / reid | 0.000 / 1.000 | 0.343 / 0.955 | S12 |
| ONNX latency p50 | 1.49 мс | 2.05 мс | 1.38× |
| params | ~4.4 M | 2.99 M | — |

Причины: (1) S04 — два чистых синуса далеко по частоте получают одинаковый
эмбеддинг, потому что таких пар нет в обучении; (2) S09 — шумовая часть
snare сливается с hihat/kick; (3) S13 — гармоники тона под шумом не
используются; (4) MUSDB — реальные стемы в обучении были моно и
панорамировались, тогда как eval/инференс работает со стерео; (5) латентность
v2.1 — четыре независимых декодера.

## Архитектура M-v3 (гипотезы)
1. **Harmonic prior.** Фиксированная subharmonic summation по лог-частотной
   оси FE-v1: `acc[b] = Σ_h P[b + 21.09·log2 h]/h`, затем
   уровень-инвариантная гармоничность `ratio = acc/mean(acc)` и
   `prior = clamp((ln ratio − ln 3)/ln 12, 0, 1)` (0 — плоский/шумовой спектр,
   1 — сильная гармоническая вершина). Prior подаётся 4-м каналом энкодера и
   остаточным логитом головы pitch. Не обучается, экспортируется в ONNX,
   считается из `feat`.
   - Измерено на FE-v1: шум −10 dBFS → медиана максимума кадра 0.17, max 0.35;
     синус 220 Гц → 0.93 на 223 Гц; пила 330 Гц → 0.91 на 331 Гц; тишина → 0.
   - Ограничение: тон, утопленный в шуме (S13: −24 дБ под −10 дБ), prior не
     выделяет; импульс/атаки drum_bed тоже дают слабый prior. Временное
     интегрирование остаётся за GRU.
   - Ограничение (измерено): при **отсутствующей основной** (только гармоники
     2–6 от 220 Гц) максимум prior уходит на 2-ю гармонику (≈430 Гц) —
     классическая октавная неоднозначность subharmonic summation. При
     присутствующей основной вершина на f0 (0.93 против 0.87 у 2-й). Prior —
     подсказка, а не решение: голова видит и полный спектр.
2. **Depthwise-separable частотный энкодер** (1×1 expand + depthwise 5 +
   1×1 project) вместо плотных 5×5: меньше MAC.
3. **Лёгкий GRU** 2×208 вместо 2×280.
4. **Общий декодер + узкие per-head адаптеры** (3×3 на голову) вместо четырёх
   полных декодеров. Голодание pitch компенсируется harmonic prior и
   отдельным адаптером.
5. Контракт шага не меняется: `feat[1,3,192]`, `h[2,1,H]` →
   `emb[1,192,20]`, `act`, `pitch`, `sal`, `h_out`. H читается C# из
   `model.json`.

## Данные M-v3
- Реальные стемы читаются **в стерео** (`read_chunk_stereo`), а не
  даунмиксятся в моно; сохраняется настоящий side-канал, как в eval.
  Аугментация стерео (ширина/поворот) применяется в пространстве L/R, поэтому
  моно-стем не теряет правый канал (D-037).
- **Hard cases** (≥30 % смешанных примеров):
  - `close_pair`: две чистые синусоиды/тона с разными f0 (в т.ч. 1–3
    полутона) и разной панорамой — прямая тренировка S04/S12;
  - `pitch_noise`: тон под шумом −18…−3 дБ (сложнее исходных −18…−6) — S10/S13;
  - `drum_bed`: одновременные kick+snare+hihat с общим темпом — S09.
  Уровни этих примеров (`relevel=False` при сведении) не перезаписываются
  случайными усилениями, поэтому заданный SNR сохраняется.
- Процедурный набор расширяется тембром `sine` (S01/S04/S13).
- Фиксированный val остаётся 120 процедурных + 120 реальных (seed 777),
  плюс hard-val (48) только для диагностики: `composite` для отбора
  чекпоинтов считается по proc+real (`sel_*` в `val.json`).

## Критерии приёмки v3
Пороги не ослабляются. v3 считается рабочей версией, если:
1. Сценарии S01–S13 ≥ 10/13 и проходят S04, S09, S13 (хотя бы один из трёх).
2. MUSDB pitch AP ≥ v1 (0.1298) на тех же 6 клипах; Slakh AP ≥ v1.
3. Tracking id_switches ≤ v2.1 (0.343/с), reid ≥ 0.955.
4. ONNX parity ≤ 1e-3, latency p50 ≤ 1.5 мс.
5. Тесты `pytest` зелёные, C# сборка и сценарии запускаются.

Если пункт не выполнен — это фиксируется в `docs/DECISIONS.md`, модель не
делается эталоном по умолчанию, но остаётся доступной в списке моделей.
